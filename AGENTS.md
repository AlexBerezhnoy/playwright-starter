# Межі роботи AI-агента

Це навчальний Playwright-проєкт. Агент допомагає створити або перевірити один тест, але не є джерелом вимог і не може оголошувати запуск успішним без фактичного output.

## Дозволено

- читати `README.md`, `specs/`, `tests/`, `labs/` і Playwright config;
- читати `.codex/agents/*.toml` для перевірки інструкцій агентів;
- змінювати лише файли, прямо названі або погоджені людиною;
- використовувати `@playwright/test` і наявні залежності;
- запускати `npm run preflight`, окремий тест і читати локальні report/trace;
- після погодження spec використовувати Playwright CLI для пошуку й перевірки
  локаторів у поточному UI перед написанням тесту;
- для Playwright CLI одразу використовувати `.playwright/cli.config.json`;
  `playwright.config.ts` призначений для Playwright Test і не передається CLI;
  перший запуск робити як
  `npx playwright cli open https://qauto.forstudy.space --config=.playwright/cli.config.json`,
  без пробного запуску з іншим config;
- позначати `FACT`, `ASSUMPTION`, `RISK`, `QUESTION` та `STOP`.

## Потрібне підтвердження людини

- запис або застосування diff;
- `APPROVE SPEC` дозволяє агенту показати точну команду відкриття CLI-сесії;
- `APPROVE CLI INSPECTION` дозволяє агенту запустити погоджену CLI-сесію,
  перевірити локатори й записати названий test file;
- `APPROVE RUN` дозволяє запустити створений Playwright Test;
- додавання залежності чи зміна config;
- будь-яка дія поза цим каталогом.

## Спеціалізовані агенти

- Делегувати роботу лише за прямим проханням людини або явно погодженим
  планом делегування. Наявність `.codex/agents/` сама по собі не є дозволом.
- Перед делегуванням перевірити відповідний TOML на суперечності з умовами
  завдання та цими правилами. За наявності суперечностей не запускати
  агента: показати їх людині й запропонувати обмежений diff до TOML.
- Передавати агенту погоджений сценарій, джерело вимог, перелік дозволених
  файлів, дозволені команди та вже отримані підтвердження.
- Делегування не розширює дозволи. Не запитувати повторно підтвердження,
  яке вже надано для тієї самої дії в погоджених межах.
- Головний агент збирає результати, перевіряє diff та фактичний output.
- Не доручати кільком агентам одночасне редагування одного файла.

### playwright_test_planner

- Планувати лише явно запитаний сценарій за наданими вимогами.
- Не додавати негативні сценарії, граничні випадки чи нові перевірки
  без прямого завдання.
- Невідомі очікування позначати `QUESTION`, а припущення — `ASSUMPTION`.
- До підтвердження запису повертати план у чаті.
- Дослідження UI потребує відповідного погодження.

### playwright_test_generator

- Генерувати один тест за погодженим spec.
- Використовувати лише підтверджені локатори й задані expected results.
- Використовувати наявні Page Objects; нові класи розміщувати в окремих
  файлах, шляхи яких погоджено людиною.
- Не записувати тест автоматично після читання generator log.
- Запис потребує наданого дозволу; запуск — окремого `APPROVE RUN`.
- Якщо агент працює в read-only режимі, він повертає запропонований diff;
  головний агент застосовує його лише за наявності дозволу.

### playwright_test_healer

- Аналізувати лише названий тест і його локальні report/trace.
- Запускати лише погоджений тест після `APPROVE RUN`.
- Спочатку визначити причину failure за evidence, потім запропонувати diff.
- Не змінювати expected results для отримання зеленого результату.
- Не додавати `test.fixme()`, `test.skip()`, fixed waits і не вилучати
  перевірки для приховування failure.
- Не запускати всі тести й не виконувати необмежений цикл виправлень.
- Для повторного запуску використовувати чинний дозвіл лише в його межах;
  за відсутності дозволу повернути результат головному агенту.

## Playwright CLI та MCP

- Для обов'язкової практики зберігається погоджений маршрут Playwright CLI.
- MCP із `.codex/agents/*.toml` дозволений лише для окремої явно погодженої
  задачі; він не є автоматичним fallback при `CLI SETUP BLOCKER`.
- Перед MCP-дослідженням показати сценарій, команду запуску сервера та
  спосіб використання локального auth config без розкриття його вмісту.
- `APPROVE MCP INSPECTION` дозволяє лише погоджене MCP-дослідження UI.
  Це не дозвіл на запис файлів або запуск Playwright Test.
- MCP write-tools підпадають під ті самі правила підтвердження запису.
- MCP test-tools підпадають під ті самі правила `APPROVE RUN`.
- Недоступність потрібних інструментів повертати як чесний blocker.

## Заборонено

- виводити в чат, terminal output або test evidence вміст `.env`,
  `.playwright/cli.config.json`, cookies чи tokens; CLI і Playwright Test можуть
  споживати локальний config без копіювання його вмісту до відповіді агента;
- змінювати baseline, config, package dependencies або product code без прямого завдання;
- використовувати непідтверджені CSS/XPath, fixed waits або вигаданий expected result;
- використовувати Browser connector для обов'язкової практики або просити
  людину вручну запускати Playwright CLI;
- виконувати commit, push, deploy або зовнішні write-дії;
- називати failure дефектом продукту до evidence-based діагностики.

## Definition of done

Є один обмежений diff, перевірені джерела локаторів та очікувань, точна команда, фактичний output або чесний blocker і рішення людини `ACCEPT` чи `STOP`.

Якщо команда `npx --no-install playwright cli --version` недоступна або preflight показує
`Playwright CLI config ready: false`, поверніть `CLI SETUP BLOCKER` і точну
інструкцію підготовки.

## Генерація тестів. 
- Перевіряти потрібно тільки те що явно вказано. 
- Не додавай самостійно перевірки
