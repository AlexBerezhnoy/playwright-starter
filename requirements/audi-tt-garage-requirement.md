# Вимога: додавання Audi TT у Garage

## Основні дії

1. Створити один UI-тест у `tests/add-car.spec.ts`, який перевіряє появу
   `Audi TT` у Garage після додавання автомобіля.
2. Запустити лише цей тест і зберегти дослівний результат запуску або blocker.
3. Опублікувати роботу у Git-репозиторії без credentials та службових файлів.

## Вхідні дані

- Готовий Playwright starter із наявними залежностями.
- Наявний `playwright.config.ts`; старт через налаштований `baseURL`.
- Умова додавання автомобіля: `specs/add-car.md`.
- Brand: `Audi`.
- Model: `TT`.
- Mileage: `12000`.

## Початковий стан

- Користувач відкрив QAuto та увійшов через `Guest log in`.
- Після входу відкрито Garage і доступна кнопка `Add car`.
- Вхід у гостьовий профіль є підготовкою до сценарію.

## Сценарій

1. Відкрити форму `Add car`.
2. У полі Brand обрати `Audi`.
3. У залежному від Brand полі Model обрати `TT`.
4. У полі Mileage ввести `12000`.
5. Зберегти автомобіль.

## Очікуваний результат

- Після збереження у Garage відображається запис автомобіля `Audi TT`.
- Для цього завдання перевіряється лише поява `Audi TT`; додаткові перевірки
  з інших прикладів не переносити.

## Запуск і підтвердження

- Запустити лише створений тест командою:

  ```bash
  npx playwright test tests/add-car.spec.ts
  ```

- Зберегти точну команду та дослівний terminal output у локальному файлі
  `run-evidence.md`. Використати структуру `templates/run-evidence.md`.
- Якщо запуск не вдався, зафіксувати фактичну причину або blocker і рішення
  `STOP`. Якщо причина ще не встановлена, прямо зазначити це.
- Не вигадувати `passed` і не називати failure дефектом продукту без діагностики.
- Не виводити credentials, cookies чи tokens у terminal output або evidence.

## Публікація роботи

- Перед публікацією перевірити склад Git diff і файлів, підготовлених до commit.
- Опублікувати тест і текстове підтвердження результату або blocker.
- Не додавати `.env`, `.playwright/`, credentials, cookies, tokens,
  `node_modules/`, `test-results/`, `playwright-report/` чи інші службові файли.
- Зберегти посилання на Git-репозиторій і commit із роботою.
- Публікацію виконує людина: чинний `AGENTS.md` забороняє агенту commit, push
  та зовнішні write-дії.

## Межі

- Один UI-тест у Chromium із використанням `@playwright/test` і наявних залежностей.
- Не змінювати config, dependencies, baseline або product code.
- Не використовувати API, registration, Fuel Expenses або fixed waits.
- Точні HTML-атрибути й CSS-класи не задані; локатори потрібно підтвердити
  за поточним UI, а не вигадувати.
- Якщо UI не відповідає умові або сценарій неможливо виконати, зафіксувати
  blocker і `STOP`, не підміняти дані чи очікуваний результат.
- Робота агента з тестом і запуском потребує окремих дозволів відповідно
  до `AGENTS.md`: `APPROVE SPEC`, `APPROVE CLI INSPECTION`, `APPROVE RUN`.

## Результат роботи

- Один тест із перевіркою появи `Audi TT` у Garage.
- Дослівний результат запуску або blocker із причиною та рішенням `STOP`.
- Посилання на опубліковану роботу без credentials та службових файлів.
